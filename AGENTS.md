# Insta360 Studio MCP maintenance

This directory owns a local Studio-only automation server. Keep target scope pinned to `C:\Program Files\Insta360 Studio\Insta360 Studio.exe`. Do not add arbitrary shell execution, arbitrary process targeting, another application's controls, cloud dependencies or credential storage to the tool surface.

Read `README.md`, `src/tools.mjs`, `src/studio.mjs`, `src/native-client.mjs`, `src/media.mjs` and the relevant native adapter code before changing behavior. Read `VALIDATION-V3.md` and `validation-v3.json` before describing current workflow coverage; preserve `VALIDATION.md` and the v2 records as history. Keep the v0.3.0 server's 21 public tool contracts aligned with the controller and adapter; document any intentional contract change. `capabilities.json` records 27 source-qualified task families, while live evidence is separate. Generic UI access and passing tool tests do not prove all 27 complete workflows. The controller reads v3 family evidence, with v2 as a compatibility fallback when v3 is unavailable.

Protect stdin/stdout framing. Node stdout is MCP JSON-RPC only, and Python stdout is its JSON-lines adapter protocol only. Diagnostics go to stderr. Preserve structured `isError` responses and explicit unknown-outcome handling.

Preserve the executable/ownership, foreground/focus, snapshot/geometry and point-hit guards. Preserve serialized MCP execution, the Windows kernel mutex and single-use observation tokens with a 120-second expiry. Bind observations and lock cleanup to the native adapter generation. Never release an old mutex by starting a replacement adapter. A timeout, protocol failure, input failure or crash must never replay input or trigger a blind retry. Reject dead-generation observations, observe and assess the resulting state first.

Preserve fresh capture on every observation and after-action result. The v0.3.0 default is JPEG quality 85, resized down to at most 1600 pixels wide without upscaling. Coordinate inputs use the returned image's pixels relative to its window, not physical desktop pixels. Map them once with integer floor scaling to the captured physical window bounds, then apply the existing physical ownership, foreground, geometry and point-hit guards. Metadata must retain returned and physical dimensions, scale factors, format and byte length. UI Automation tree bounds remain physical desktop pixels and must be labeled `accessibility.bounds_coordinate_space: "physical desktop pixels"` in both compact and full responses. Use the current `element_id` for an accessibility target; never copy its physical bounds into screenshot-relative `x`/`y`. UI Automation element input remains a separate native route. Never infer coordinates from a previous frame or reuse a cached image.

Keep response detail compact by default, preserving observation tokens, coordinate metadata, action IDs, delivery state and visual-verification requirements. Resolve initial omitted `include_text` automatically: on only for native `#32770` dialogs, off for Studio Qt windows. Skipping text must skip both accessibility-tree and focused-control queries. An explicit `include_text: true` or `false` persists; `include_text: "auto"` resets that explicit choice and resolves inspection from each newly observed window, including action results and `studio_wait_ready`. Omitting the option retains the current preference rather than resetting it. `output_detail: "full"` restores expanded observation/action metadata. `image_max_width: 0` with `image_format: "png"` requests original PNG pixels. Latest successful capture preferences carry into after-action observations and `studio_wait_ready`; failures must not make a stale observation reusable. `studio_capabilities` defaults to a summary; a family request or `detail: "full"` supplies sources, eligibility and family evidence. Benchmark payload sizes and timings separately from provider-billed tokens; image compression does not establish an exact Codex or Claude token saving.

Preserve the `GetLastInputInfo.dwTime` baseline captured after activation/settling and checked again after screenshot, UI inspection and metadata collection. Reject input activity during observation before issuing a usable snapshot. Preserve the initial input-activity check on all eight input methods, before activating Studio or delivering the action. Changed desktop input must invalidate the snapshot/visual-focus anchor with `manual_input_detected`; unavailable evidence must reject rather than assume inactivity. This includes input from another MCP/client and cannot distinguish physical from injected input. It does not detect every interruption during a running multi-second action. Keep the desktop idle, retain ongoing foreground/focus/geometry guards, and re-observe after activity. Check filename, destination and settings immediately before Export; chat typing can reach Studio fields when Studio owns focus.

Keep hover, modifier clicks, repeated keys and timed polyline drags bounded and Studio-only. Mouse actions accept left/right/middle buttons and distinct Ctrl/Shift/Alt modifiers; Win/Meta and app/desktop-switching chords remain forbidden. Validate every drag path point and recheck ownership/focus/geometry during motion. Preserve held-button/modifier release cleanup on failures, including partial delivery. Never let cleanup erase the primary error or turn an uncertain action into success. Keep action IDs and `delivery_state` (`not_delivered`, `delivered`, `unknown`) in errors/logs; a delivered action still requires visual verification.

Use literal UTF-16 typing. Default text entry requires an editable focused UI Automation control. Screenshot typing is a deliberate exception for unexposed Studio Qt text fields: it requires a visible field clicked in the same window, inspection of the click result, its fresh token and unchanged native focus. Do not broaden this to arbitrary focused controls. `replace` must remain explicit and default to false. A separate observation clears the visual click anchor.

Keep source media intact. Use synthetic footage or isolated copies of original camera files with matching paired media for live implementation checks. Import must go through a verified Studio-owned open dialog with 1–32 existing absolute local media paths. Keep MP3/WAV/LRV extensions aligned across schemas/controller/native adapter: imported MP3/WAV music belongs on Project, and documented LRV import is supported on both pages. An accepted extension does not prove page/codec/camera-mode eligibility. Never silently overwrite, rename or delete original footage.

Treat delivered input and successful editing as separate evidence. Return and inspect the after-action screenshot. Report only what the actual Studio state and output support. Update `VALIDATION-V3.md` and family-specific `validation-v3.json` with recorded results and limitations; do not overwrite historical evidence or mark every Studio task proven after one clip. `studio_wait_ready` establishes window readiness, not hidden analysis/export completion. Exact menu positions, shortcuts and parameter ranges must be observed in the installed version.

Keep export checks honest. Take a `studio_export_checkpoint` on the exact intended output before Export; reject unchanged pre-existing files, while stating that file change alone does not prove Studio authorship. Quick verification checks stable file identity/state, FFprobe metadata, supplied duration/resolution/FPS/codec/audio expectations and first-second video/audio decoding. Do not describe it as a full decode. Full mode starts an asynchronous owned FFmpeg child: report success only after polling `studio_verification_status` yields `completed` with `ok: true`, final unchanged-file checks and full verification depth. Visual/audio review and intended-edit comparison remain necessary for final delivery.

Preserve full-job limits, bounded decode timeouts, progress, atomic checkpoint/job persistence and read-only media inspection. Cancel only this session's tracked verification child, never Studio or an arbitrary/saved PID. Preserve errors and status uncertainty when termination is requested but exit is not confirmed; `running`, `cancelling`, `timing_out`, `process_error`, `termination_failed` and `termination_unconfirmed` are not successful completion. After restart, persisted active records may be stale and cannot be treated as live process proof. Expose persistence failures and flush pending final records at orderly shutdown.

Action logs must redact literal `text` and `value` as hash plus length. Do not persist screenshots during normal server use. The developer live client may save explicit validation captures into the ignored `artifacts/` folder. Keep media subprocess executables pinned to configured absolute local FFprobe/FFmpeg paths and shell execution disabled. `runtime/`, `logs/` and `artifacts/` remain ignored; do not place credentials in records.

Run checks appropriate to the change:

```powershell

```

For a live integration check, open Studio and run `npm.cmd run smoke -- --require-window`. Observation can bring Studio to the foreground. Use a synthetic clip or isolated camera-media copy when validating input/import/export. Update v3 evidence with actual results and limitations; do not treat mocked tests as proof of a real editing workflow. Verify new tool contracts, native-generation/error recovery, held-input cleanup, image scaling/preference persistence and media verifier outcomes with appropriate automated tests; precise test counts belong in validation evidence. `scripts/benchmark.mjs` measures protocol/text payload sizes and latency without GUI capture by default; `--observe` adds fresh native captures and requires an idle desktop. Keep benchmark failures and small-sample limitations visible.
