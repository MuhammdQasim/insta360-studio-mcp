# Insta360 Studio capability inventory

Checked **14 October 2026** for the local **Studio 6.0.2** MCP. The official sources below identify task families and restrictions; they are not proof that every task was executed on this computer.

`capabilities.json` is the machine-readable inventory of 27 task families. Its `available_through_observed_UI` status means a route through the MCP's observed screen and generic input tools. It does not mark a task family as proven. [VALIDATION-V3.md](VALIDATION-V3.md) is the current local evidence; `validation-v3.json` records per-family results. The `studio_capabilities` tool merges those results with this inventory, falling back to v2 evidence when v3 is unavailable. It returns a compact summary by default; request a family ID or `detail: "full"` for sources, eligibility and live results. [VALIDATION.md](VALIDATION.md) and [VALIDATION-V2.md](VALIDATION-V2.md) preserve historical checks.

The v0.3.0 MCP has 21 tools: observed UI input, hover for tooltips, modifier clicks and scrolling, bounded key repetition, timed drag paths, window readiness, local metadata, checkpoints and quick/full export verification. Exact contracts and recovery instructions are in [README.md](README.md). These interaction tools are access routes; passing all tool tests does not establish all 27 Studio workflows or remove Studio's media/page/version restrictions.

Every observation and after-action screenshot is fresh. The default is a JPEG at quality 85, reduced to at most 1600 pixels wide without upscaling, with compact text metadata. Click, hover, scroll and drag coordinates refer to pixels in the returned image relative to its window. The adapter maps those points to the captured physical window bounds; executable ownership, foreground/focus, physical geometry and point-hit checks remain active. Screenshot metadata includes both dimensions, scale factors, format and encoded byte length. UI Automation tree bounds use physical desktop pixels, labeled `accessibility.bounds_coordinate_space: "physical desktop pixels"`; use the current `element_id` for a tree target. Never pass those physical bounds as screenshot-relative `x`/`y`.

Text inspection initially defaults to automatic selection: native `#32770` dialogs receive UI Automation inspection; Studio Qt windows skip the tree and focused-control queries. Explicit boolean choices persist through subsequent after-action observations and window readiness checks, as do image and response-detail preferences. Use `include_text: "auto"` to reset a boolean choice and follow the current window type again; omitting the option keeps the current preference. Expanded metadata and original pixels remain available:

| Observation option | Result |
| --- | --- |
| Omit capture options in a new session | Fresh JPEG, maximum width 1600, quality 85, compact output; automatic dialog text inspection. Later omissions retain saved preferences. |
| `include_text: true` | Inspect the bounded UI Automation tree and focused control; available element IDs require this inspection. |
| `include_text: "auto"` | Reset an explicit boolean choice; inspect native dialogs and skip Qt inspection, including later action/readiness results. |
| `output_detail: "full"` | Expanded window, accessibility and action metadata; does not change image resolution or format. |
| `image_max_width: 0, image_format: "png"` | Original physical screenshot pixels encoded as PNG; returned coordinates use that original image. |

Smaller images and shorter metadata reduce transport payload. Actual Codex and Claude billing depends on the client/model, image processing, tool context and caching. The benchmark reports capture/response timing, bytes and a stated text-size heuristic; it does not measure provider-billed tokens or prove an exact token-saving percentage.

Keep the desktop idle during control. Desktop input during capture/UI inspection rejects the observation; input after an observation, including another automation client, invalidates the next input as `manual_input_detected`. Obtain a fresh observation and inspect the current state after activity. The Windows last-input-time check cannot identify who generated input or detect every interruption during a running action. Studio may own keyboard focus, so recheck text fields and export destination/settings before proceeding. Observation tokens remain single use and expire after 120 seconds; a separate observation clears the clicked-field anchor used for deliberate Qt screenshot typing.

**Evidence limits:** consult the current v3 validation record for the exact tested clip, actions, outputs and remaining gaps. A successful import/preview/trim or export on one source does not establish all stitching/stabilization, keyframe/Deep Track/Movement, timeline/resource, color/audio or long/batch workflows. Exact installed menu positions, shortcuts and parameter ranges must come from a fresh observation. Preserve original footage throughout testing. `studio_wait_ready` establishes matching window readiness, not completion of media analysis or export.

Export verification distinguishes a stable playable file from a newly produced edit. Take a checkpoint before Export, provide expected settings, and poll full-decode jobs to confirmed completion when needed. Quick mode checks only the first second of video/audio; full decoding still needs visual/audio review. Cancellation and persisted uncertain job states are not successful verification. See the README for status and recovery details.
